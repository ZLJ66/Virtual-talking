### 一个练习英文表达的软件

> 软件的设想基于我的一个梦境：
在梦里，我和老爸在国外的一个商店中购物，在我们把钱交给收银员之后，收银员对我爸说了一句英文。我爸不懂英文，而我又只听到了半句话，便以为他所表述的是“祝你们生活愉快”之类的话语，便拉着我老爸离开的商店。我走了几步路，回想了下，发现收银员好像是想说他要找零钱给我们。意识到这一点后，我跟老爸说了这件事，便自己跑回商店了。正当我开口向收银员询问是否可以把刚刚的零钱给我的时候，我突然意识到我的英文表达有些笨拙，甚至有些结巴，似乎就是突然到了一个实际的英文场景的时候，我就不太会表达了。虽然最后我成功地表达出了正确的意思，但我觉得这还不够好，我需要更加完美。

于是开发这个软件的想法便诞生了，我大概是这样设计的：

- 这类似于一个文字游戏。用户需要事先设置好一些基本信息，比如名字、性别等。游戏有一个可供用户选择的故事基调，比如说：主角前往英国留学......或主角在澳大利亚定居......（我这里随便编了两个开头，到时候会再讨论确定添加）。
- 在用户选择好故事主线之后，游戏便正式开始了，主角会不断碰到一个个实际的英文场景，用户需要输入自己要表达的英文句子（至于是用语音输入还是打字输入，还是其它的输入方式，我觉得我们可以先做打字输入的版本，之后再添加丰富的功能）。然后程序的内置ai会即时推演用户在表达完之后会发生什么。举个例子，比如在某个场景中，用户输入：“I'm not feeling well.”之后，npc也许会说一句：“Do you need to go to the hospital for a check-up?”。
- 用户除了可以自己输入要说的话语之外，还可以输入要做的动作（区别于话语的输入框，动作的输入框既可以填中文也可以填英文），继续以刚刚的例子介绍，用户在话语的输入框中输入：“I'm not feeling well.”之后，还可以同时在可选的动作的输入框输入：“捂着肚子，微微皱眉”。如果用户没有输入动作的话，有时候旁白也会自动配上一定的动作（在合适的情况下）
- 软件有一个旁白系统，还是刚刚的例子，在用户结束输入：“I'm not feeling well.”之后，应先介入旁白系统，旁白播报：XX（npc）快速审视了下你的脸色。然后再是npc说话：“Do you need to go to the hospital for a check-up?”至于旁白要用英文还是中文播报，我觉得可以让用户随时切换，用户想用中文播报就中文播，想用英文就用英文。
- 软件还有一个重要的功能：打断。比如说，在npc说了半句话后，用户突然想打断npc的话语或动作，从而说几句话或者做某些动作，可以点击“打断”按钮，这时程序会暂停，然后用户就可以输入话语、动作从而事先打断旁白或npc了。

## 演进说明

> 本节为后续补充，用于说明原始构想中哪些部分已被取代。**正文保持原样。**

### 已被保留的设计

| 原始构想 | 现状 |
|---|---|
| 文字游戏形态 | ✅ 保留。MVP 明确不做语音与图像 |
| 用户预先设置基本信息（名字、性别等） | ✅ 保留并扩展为「角色档案」，见 [`产品文档.md`](产品文档.md) 功能 01 |
| 自由输入英文，AI 即时推演 | ✅ 保留，且被确认为**最核心功能** |
| 独立的动作输入框（中/英皆可） | ✅ 保留，见功能 03 |
| 旁白系统，中英可随时切换 | ✅ 保留。实现上采用**结构化事件存储**，切换语言时重新呈现而非重跑剧情 |
| 打断机制 | ✅ 保留，并扩展为「打断 / 暂停 / 请求重复」三种行为 |

### 已被取代或调整的设计

| 原始构想 | 取代者 | 原因 |
|---|---|---|
| 「故事基调」可选（英国留学 / 澳洲定居…） | **先只做一个世界（英国留学第一周）** | 内容成本集中，先做深一个再扩展。`StoryBackground` 其余选项暂作占位 |
| 「不断碰到一个个实际的英文场景」 | **8 个地点的可自由移动世界** | 线性走廊产生"关卡感"，见 [`世界层设计.md`](世界层设计.md) 1.1 |
| 场景由剧情顺序推进 | **玩家主动选择去哪** | 自主权是消除关卡感的核心机制 |
| 旁白"有时候自动配上动作" | 保留，但改为**由世界状态与场景卡驱动**，非随机生成 | 避免套路感，见 [`世界层设计.md`](世界层设计.md) 6.1 |

### 新增的、原始构想中没有的设计

- **世界时钟**：时间只被移动消耗，对话不消耗（否则等于用英语水平惩罚玩家）
- **NPC 印象标签与记忆**：让 NPC 记住玩家，而非每次都像陌生人
- **主线基于真实行政流程**：英国大学注册的因果链，而非人造关卡
- **错过截止不惩罚**：后果转化为新剧情，而非失败

> 以上变更的完整决策记录见 [`世界层设计.md`](世界层设计.md) 附录 A。
