> 版本：v1.1 · 状态：现行路线图

## 一、MVP 目标

### 1.1 一句话目标

**做出一个能完整体验 10～20 分钟的"垂直切片"**：从角色设置 → 进入世界 → 在 8 个地点间自由移动 → 与 NPC 自由对话与行动 → AI 推进剧情 → 打断/旁白交互 → 英语反馈 → 存档续玩，所有核心系统完整运行。

> **v1.1 关键变化：从"一条线性故事线"改为"一个小世界"。** 用户不再被系统推着走完三个场景，而是自己决定去哪里、先办哪件事。

### 1.2 MVP 验证的核心假设

| 假设 | 如何验证 |
|---|---|
| 用户在剧情中会**真正自己组织英文**（而非依赖提示） | 观察输入行为 + 复盘参与度 |
| **自由表达 + 动态剧情 + 即时学习反馈**能提升表达信心 | 试玩问卷 + 进步指标初值 |
| AI 作为"世界引擎"能维持**剧情连贯** | 跑通一条完整主线无明显事实矛盾 |
| 打断/旁白/动作让体验**更像真实对话**而非机械问答 | 试玩主观反馈 |
| **（v1.1 新增）世界层能消除"关卡感"** | 用户是否感到"在同一个世界活动"、"去哪里由我决定" |
| **（v1.1 新增）NPC 记忆能产生"被记住"的感受** | 用户是否注意到 NPC 记得之前的事 |
| **（v1.1 新增）同一世界可重复游玩** | 换一套 NPC 人设后，用户是否愿意再玩一次 |

> MVP 不追求用户规模，而追求"核心假设是否成立、核心循环是否可玩"。

### 1.3 关于范围膨胀的说明

**本版本显式承认：世界层扩展超出 v1.0 的 9 项清单。** v1.0 将"开发范围膨胀"列为风险，对策是"严格守住 9 项清单"。

既然已决定引入世界层，正确处理方式是**正式修订范围并记录理由**，而非一边做世界系统、一边觉得自己在拖延 MVP。**未受控的膨胀是风险，受控的扩展是决策。**

## 二、MVP 功能清单（11 项）

| # | 功能 | 说明 | 变化 |
|---|---|---|---|
| 1 | 基本角色设置 | 名字、英语水平、故事背景、旁白语言 | 不变 |
| 2 | **一个世界 + 一条主线** | 英国留学第一周；主线：安顿下来 | 🔄 替换原「一个完整故事」 |
| 3 | **8 个地点，可自由移动** | 宿舍、便利店、公交站、超市、注册处、银行、咖啡馆、导师办公室 | 🔄 替换原「3~5 个生活场景」 |
| 4 | 自由英文输入 | 用户输入任意合理的英文表达 | 不变 |
| 5 | 中文/英文动作输入 | 描述表情、动作或观察到的环境 | 不变 |
| 6 | 动态旁白与 NPC 对话 | AI 按顺序生成叙事事件 | 不变 |
| 7 | 文字打断机制 | 停止当前播放并允许用户插话 | 不变 |
| 8 | 基础英语反馈 | 表达有效性、自然度、参考表达 | 不变 |
| 9 | 剧情自动保存 | 退出后可继续上次的故事 | 🔄 机制重写为事件流 |
| 10 | **世界时钟与时段** | 六时段；仅移动消耗时间；错过截止产生新剧情 | ✨ 新增 |
| 11 | **NPC 记忆与印象标签** | 跨场景记住玩家，不因英语水平改变关系 | ✨ 新增 |

### MVP 明确不做

- 语音识别 / 实时语音对话
- AI 视频 / 角色动画 / 复杂立绘
- 多人联机
- 完全开放世界 / 无限制剧情生成
- 复杂等级、装备、货币、成就系统
- 大规模预制故事库
- **主持人调度器（v1.1 明确延后）**
- **多世界（澳洲移民 / 旅行者，v1.1 明确延后）**

> **注意：** "不做完全开放世界"与第 3 项"8 地点自由移动"**不矛盾**。地点是离散的、预先设计的、数量有限的；玩家只在地点间选择，不做自由文本移动。

## 三、技术栈

| 层 | 选型 | 职责 |
|---|---|---|
| 前端 | React + TypeScript | 故事页面、对话框、话语/动作输入、打断按钮、旁白展示、角色档案、**地点选择**、学习报告 |
| 后端 | Python + FastAPI | **世界层**、游戏状态、剧情规则、AI 请求、会话记录、英语评估 |
| **内容数据层（v1.1 新增）** | **YAML + Pydantic 校验** | 世界圣经、地点卡、NPC 卡、主线定义 |
| 数据库 | SQLite（后续可升 PostgreSQL） | 用户设置、**事件流**、学习记录 |
| 大模型 | 支持结构化输出 + 流式输出的模型 API | NPC 对话、旁白、场景反应、英语反馈 |
| 交付形态 | 先 Web 跑通核心玩法，未来可用 Tauri/Electron 打包桌面端 | — |

> 选型理由：React 适合丰富交互式文字游戏界面；Python 生态利于快速开发 AI 应用与文本处理；FastAPI 利于前后端分离与后续接语音；SQLite 免部署、适合单人开发早期版本。
>
> **v1.1 新增内容数据层的理由：** 感官细节、NPC 性格、台词风格全是散文，JSON 没有多行字符串和注释，对内容作者是折磨；YAML 少一半标点噪音且支持注释（可留 TODO）。用 Pydantic 校验是因为它已在 [`main.py`](../backend/main.py) 中使用——同一套模型既能校验 API 请求，也能校验内容文件，**模型即代码，不会与文档漂移**。
>
> **关键机制：启动时校验，不通过就报错。** 内容错误是"AI 表现奇怪"的头号原因——地点卡少一个字段，AI 会静默降级，你根本不知道哪里错了。**启动时炸掉，好过运行时悄悄变傻。**

### 阶段 A：世界层地基

**目标：** 把线性场景结构改造成可自由移动的小世界，消除关卡感。

**产出：**
- 世界 / 地点 / NPC 数据模型定义（Pydantic）
- YAML 内容加载器 + **启动时校验**
- 状态模型重写：`sceneIndex`/`stepIndex` → `location` / `time` / `facts` / `npc_states`
- 地点选择 UI（可达地点列表，替代"前往下一场景"按钮）
- **"离开"变成玩家的动作**——不再由系统判定场景完成后推送
- 转场携带真实上下文（世界状态快照 + 最近事件 + NPC 关系，替代一句摘要）
- 统一开场与回合的 prompt（消除 NPC 性格漂移）
- 地点重入分级（进入深度判定，第 4 次起 0 次 AI 调用）
- 第一批内容：3 地点 + 3 NPC + 1 条主线（宿舍、便利店、注册处）

**里程碑 M-A · 世界可移动**
**验收标准：**
1. 玩家可在地点图自由移动，"离开"由玩家发起
2. 转场旁白能引用上一场景的**真实事实**（而非通用套话）
3. 同一地点二次进入不再重播完整开场
4. 内容改 YAML 文件后重启即生效，无需改代码
5. 内容文件字段缺失时**启动即报错**
6. 打断 / 暂停 / 请求重复 / 双语旁白 / 反馈面板**无回归**

---

### 阶段 B：世界活起来

**目标：** 让世界有时间、有记忆、有主线，NPC 不再是陌生人。

**产出：**
- 世界时钟：六时段、移动消耗、跨日结算、营业时间判定
- 「原地等待」交互（消耗 1 时段，世界推进一拍）
- NPC 印象标签 + 记忆：写入判据、容量上限、注入 prompt
- 主线判定器：节点条件检查、世界事实写入
- 截止与**软后果机制**：错过 → 世界记住 → 产生新场景
- 状态变更校验层（拒绝 AI 移动玩家 / 推进时间）
- 兜底规则表：越界行为 / 无处可去 / 无关话题 / 反复进出
- 每个主线节点定义 `soft_paths`

**里程碑 M-B · 世界有记忆**
**验收标准：**
1. 一条主线可完整走完（报到 → 开户 → 见导师）
2. 玩家二次遇到同一 NPC 时，NPC 能引用上次的事
3. 玩家故意错过截止，产生"解释与请求通融"的新场景，**游戏不中断、不判失败**
4. AI 提议移动玩家或推进时间时被代码拒绝，回合不中断
5. 玩家在任何情况下都不会永久卡死（软路径可用）

---

### 阶段 C：血肉随机

**目标：** 解决"每次玩都差不多"，让同一世界可重复游玩。

**产出：**
- NPC 人设候选池（每个角色位 2~3 个候选，开局随机抽取）
- 天气 / 时段随机
- 主线节点走法变体（节点固定，路径随机）

**里程碑 M-C · 同一世界，不同体验**
**验收标准：** 连续两次游玩，NPC 人设与事件细节不同，但世界结构与主线一致。

---

### 阶段 D：持久化与学习闭环

**目标：** 退出可续玩；英语反馈形成闭环。

**产出：**
- 事件流持久化（SQLite，append-only）
- 只保存"已生效"事件（打断中途关闭不存半句台词）
- 退出后重放恢复世界状态
- 三种练习模式的反馈时机实现（沉浸 / 学习 / 挑战）
- 个人学习档案：从事件流派生薄弱环节
- 进步指标记录（含**提示依赖程度**，来自退路机制记录）
- 邀请真实用户试玩

**里程碑 M-D · 核心循环闭环（MVP 完成）**
**验收标准：**
1. 关掉程序再打开，能从上次进度继续，世界状态完整
2. 用户能完成主线并获得英语反馈
3. 试玩反馈收集到位，MVP 核心假设得到初步验证或明确调整方向

---

### 阶段 E（预留）：主持人调度器

**触发条件（满足任一才启动）：**
- 玩家做出**改变世界状态**的事，规则表无法覆盖
- 回合 AI 反复生成与事实矛盾的内容
- 需要主动制造剧情张力

**产出：** 轻量节拍表调度（下一拍该是"顺利 / 小挫折 / NPC 主动发起 / 意外事件"）。

> **当前不做。** 架构图中的「游戏控制层」已为此预留位置。避免过度设计——先让兜底规则表覆盖已知情况。

## 六、贯穿全程的关键工程纪律

> **v1.1：由 5 条增至 7 条。**

1. **状态由代码管理，AI 只在规则内生成** —— 不把整条聊天记录丢给大模型让它随便答。
2. **结构化输出 + 数据校验** —— AI 按固定 JSON 返回，程序校验后才接受状态变更，不直接信任 AI 改的金额/任务/场景。
3. **区分"展示中"与"已生效"事件** —— 打断只停显示，不回滚已成事实。
4. **控上下文、按需调用评估** —— 控制 AI 调用成本，英语评估按模式与需触发。
5. **每阶段完整流程测试** —— 不等全部写完才验证协同。
6. **（v1.1 新增）AI 不得移动玩家，不得推进时间** —— 移动是玩家的主动权；时间只被移动消耗。这两条是消除关卡感与避免时间困惑的底线。
7. **（v1.1 新增）关系度不由英语表达质量驱动** —— 否则等于用英语水平给玩家的人际关系打分，违背"敢错氛围"核心原则。

> **v1.1 补充说明第 1 条：** 具体化为"AI 返回的 `world_changes` 只是**提议**，代码校验通过后才生效"。拒绝规则见 [`世界层设计.md`](世界层设计.md) 5.6。

## 七、风险与应对（开发视角）

> **v1.1：新增 4 项风险。**

| 风险 | 影响 | 应对 |
|---|---|---|
| AI 输出格式不稳定 | 解析失败、剧情错乱 | 结构化输出 + 校验 + 重试；程序决定是否接受状态变更 |
| 剧情前后矛盾 | 体验崩塌 | 预设剧情节点，AI 在节点间生成；程序管世界状态 |
| 打断后状态错乱 | NPC 忘记已发生的事 | 回合唯一标识 + 生成任务取消/过期处理 + 区分展示/生效事件 |
| 开发范围膨胀 | 永远没有可玩版本 | **v1.1：已显式重定义 MVP 范围（11 项）并记录理由**，而非继续压缩。阶段 A 严格限定 3 地点 |
| AI 调用成本失控 | 难以持续运营 | 控上下文长度、限生成、按需调用评估。**v1.1 新增：地点重入分级（第 4 次起 0 次调用）** |
| API 密钥泄露 | 安全事故 | 密钥仅在服务端，客户端不持有 |
| **（v1.1 新增）状态模型重写引入回归** | 打断/反馈等已有功能损坏 | 交互层与事件流保留不重写；阶段 A 验收含回归检查（第 6 条） |
| **（v1.1 新增）内容过时** | 政策变化（如 BRP→eVisa）使场景失真，且过时得很隐蔽 | 世界圣经锁定年份；政策类内容集中标注 |
| **（v1.1 新增）自由度过高导致 AI 接不住** | 玩家做出预料之外的事，回合 AI 无法处理 | 兜底规则表覆盖已知情况；预留调度器位置；每个主线节点必须定义 `soft_paths` |
| **（v1.1 新增）AI 提议的状态变更被误信** | 世界事实被污染，主线判定错误 | 代码校验层强制拦截（拒绝 AI 移动玩家/推进时间/凭空写入事实） |

## 八、MVP 完成后的下一步（非本规划范围）

- 基于试玩反馈打磨核心循环与反馈质量
- **扩充当前世界的地点与 NPC**（从 8 个地点扩展到更完整的城市）
- **新增更多世界**（澳洲移民、海外旅行者）
- **主持人调度器**（若阶段 E 触发条件成立）
- 评估是否引入语音输入（在文字版跑通后）
- 评估桌面端打包形态（Tauri/Electron）

> 这些均为 MVP 验证通过后的决策项，不在当前开发规划内。

> **v1.0 → v1.1 的变化：** 原「增加第二条故事主线」改为「扩充当前世界」——因为世界层的正确扩展方式是**在同一个世界内加地点**，而非并列增加互不相干的故事线。并列故事线会重现 v1.0 的"关卡感"问题。
